# JanMaang — Flutter Architecture (Phase 2)

## Stack
Flutter · Dart · Material 3 · Riverpod · go_router · Firebase (Auth, Firestore, Storage,
Functions, Messaging, Analytics, Crashlytics) · Google Sign-In · Google Maps · Gemini (server-side only)

## Layering

```
presentation  (widgets, screens, Riverpod notifiers)
      |  depends on
domain        (entities, repository interfaces, failures)
      ^  implemented by
data          (DTOs, Firestore/Storage/Functions datasources, repository impls, mocks)
```

Presentation never imports `cloud_firestore`. Repositories are exposed as Riverpod providers,
overridden at the composition root (`main.dart`) to swap mock ⇄ Firebase.

## Data model (Firestore)

| Collection | Doc | Key fields |
|---|---|---|
| `users/{uid}` | citizen | phone, displayName, photoUrl, district, ward, aadhaarVerified, trustLevel, fcmTokens[], createdAt |
| `demands/{id}` | one citizen report | code (YDG-WTR-0417), reporterId, title, transcript, category, severity, status, geo (GeoPoint), ward, district, photoUrls[], clusterId, supporterCount, rank, priorityScore, scoreBreakdown{peopleAffected, infrastructureGap, equityIndex, severity, durationUnaddressed}, createdAt, updatedAt |
| `demands/{id}/supporters/{uid}` | join record | uid, joinedAt |
| `demands/{id}/timeline/{n}` | status events | status, label, note, at |
| `clusters/{id}` | merged demands | code, title, category, demandIds[], reportCount, mergedDuplicates, habitationsAffected, peopleAffected, centroid, boundsRadiusM, rank, totalRanked |
| `verifications/{id}` | citizen/field verification | demandId, verifierId, kind (citizen\|field), fixed (bool), checklist{}, photoUrls[], geo, at |
| `ledgerEntries/{id}` | public ledger | demandId, clusterId, title, amount, currency, department, fiscalYear, stage, verifiedByCitizens, at |
| `allocations/{id}` | budget allocation | clusterId, amount, approvedBy, approvedAt, status |

Storage: `reports/{uid}/{demandId}/{uuid}.jpg`, `verifications/{verificationId}/{uuid}.jpg`.

## Cloud Functions (server-side, holds all secrets)

| Function | Trigger | Job |
|---|---|---|
| `analyzeReport` | callable | Gemini: transcript/photo → category, severity, summary, extracted location, translation |
| `clusterDemand` | Firestore onCreate `demands/{id}` | geo + category + embedding similarity → attach/create cluster |
| `computePriority` | scheduled + onWrite | 5-factor score → rank across district |
| `onDemandStatusChange` | Firestore onUpdate | FCM push + SMS/WhatsApp hook |
| `submitVerification` | callable | validates geotag/timestamp, writes verification, advances status |

**No Gemini/Maps server key ships in the Flutter app.** The client only ever calls
`FirebaseFunctions.httpsCallable`. Firestore Security Rules restrict writes to the
authenticated reporter; ranking, cluster and ledger fields are server-write-only.

## State management

Riverpod 2, hand-written providers (no codegen). Pattern per feature:
`repositoryProvider` (overridable) → `AsyncNotifierProvider` for screen state →
`ref.watch` in widgets. Streams (`demandsStream`) via `StreamProvider`.

## Routing (go_router)

`StatefulShellRoute.indexedStack` for the 4-tab bottom nav (Home · Track · Report · Ledger).
Transactional routes (`/login`, `/login/otp`, `/report/*`, `/verify/:id`,
`/field-verification/:id`, `/onboarding`) sit outside the shell — matching Stitch, which
suppresses the bottom nav on those screens. `redirect` guards on auth state.

## Mock-first

`AppConfig.useMocks` defaults to true until `flutterfire configure` is run, so the whole
UI is navigable and testable without a Firebase project. Mock repositories return the exact
fixture data shown in the Stitch designs (41 demands, 4,281 affected, YDG-WTR-0417, rank #2
of 214, the 5 score factors, the 7-step timeline).
